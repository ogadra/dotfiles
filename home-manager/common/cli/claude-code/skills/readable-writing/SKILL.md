# Readable Writing

対象の文章を7観点で並列にレビューし、集まった指摘をすべて修正する。レビューは `scripts/review.sh` が観点ごとに `claude -p` を起動して行う。

成果物は修正後の文章だけ。指摘の一覧、修正した箇所の説明、作業の報告は出力しない。

## 対象

- 技術文書
- README
- コミットメッセージ
- PR説明
- コード内コメント
- 実装計画書
- 設計書

自然言語だけを見る。

## 大原則

AIに書かせた文章が読みにくいのは、書き手が文面から消えるからだ。何を見て、何に引っかかって、どこまで言い切るのかを自分で決めずにAIへ渡すと、そこが抜け落ちる。記号や語彙の読みにくさは、その症状として表に出る。

## 引数

- `$1` はレビュー対象。次のどれかを取る
    - ファイルパス
    - ディレクトリ
    - 直前に自分が書いた下書き
- ユーザーが `$1` を渡さなければ、対象を確認する

## 手順

### 1. 対象の確定

- ファイルパスの場合
    - そのパスを使う
- ディレクトリの場合
    - Globでファイルを集め、対象をユーザーに確認する
    - ファイルごとにステップ2から繰り返す
- 会話中の下書きの場合
    - 一時ファイルに書き出してそのパスを使う

### 2. 並列レビューの実行

`scripts/review.sh` を実行する。観点ごとに `claude -p` を並列で起動し、findingsを1つのJSON配列にまとめて標準出力に出す。

```bash
bash ~/.claude/skills/readable-writing/scripts/review.sh <ファイルパス>
```

言語は文字種から判定する。判定を上書きするときだけ第2引数に `ja` `en` `both` のどれかを渡す。

```bash
bash ~/.claude/skills/readable-writing/scripts/review.sh <ファイルパス> both
```

出力は次の形。

```json
[
  {
    "perspective": "立場",
    "file": "<ファイルパス>",
    "line": 12,
    "quote": "<該当箇所の原文>",
    "category": "<ポリシー内の該当節名>",
    "problem": "<何が読みにくいか1文>",
    "fix": "<書き換えた後の文そのもの>"
  }
]
```

スクリプトが非ゼロで終了したら、標準エラーの内容をそのままユーザーに見せて止まる。

#### 観点とポリシーファイルの対応表

スクリプトが `policies/` 配下から、観点ごとに `common/`、`ja/`、`en/` の該当ファイルを集めてプロンプトに埋め込む。

| 観点 | ファイル | 見るもの |
|---|---|---|
| 立場 | `stance.md` | 書き手が何を引き受けているか |
| 主体 | `agency.md` | 誰が何をしたか |
| 箇条書き | `lists.md` | 箇条書きの階層と粒度 |
| 文書構成 | `document.md` | 見出し、節、情報の取捨 |
| 修辞 | `rhetoric.md` | 構文の型とリズム |
| 語彙 | `vocabulary.md` | 語の選択 |
| 記号 | `symbols.md` | 記号と字面 |

### 3. 結果の統合

スクリプトが返したfindingsを、出力せずに手元で統合する。

- 同一の `quote` を指す重複は1件に統合する。
- 並び順
    - ファイルパス昇順
    - 行番号昇順
- `quote` が本文に実在しない指摘は捨てる。
- 原文を読み、ポリシーに照らして妥当でない指摘は捨てる。

残った指摘はすべて直す。優先順位や重みは付けない。

### 4. 修正

- 対象ファイルをReadで開き、`quote` の前後を読む。
- `fix` をそのまま貼らない
    - 前後の文と繋がるように書き換える
- 同一段落への修正が複数ある場合
    - 段落ごとにまとめて書き換える
- 立場と主体の指摘から先に直す
    - 段落を組み直すと、記号と語彙の指摘が消えることがある
- 書き換えるときは、別の観点のポリシーに違反しないか確認する
    - 二項対比を消して括弧に逃がす、といった置き換えをしない
- 直し方に迷った場合
    - 該当ポリシーのAI版と修正版の対比を読む
- 指摘の無い箇所を書き換えない。

### 5. 成果物の提示

- ファイルが対象の場合
    - Editで書き換えて終わる
- 会話中の下書きが対象の場合
    - 修正後の本文だけを出力する

指摘が0件なら「修正なし」とだけ返す。
