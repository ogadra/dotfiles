# Readable Writing

成果物は修正後の文章

自然言語だけを見る

## 観点とポリシー

ポリシーファイルは `policies/` 配下

- `common/`
- `ja/`
- `en/`

| 観点 | ファイル | 見るもの |
|---|---|---|
| 立場 | `stance.md` | 書き手が引き受ける範囲 |
| 主体 | `agency.md` | 行為の主体 |
| 箇条書き | `lists.md` | 箇条書きの階層と粒度 |
| 文書構成 | `document.md` | 見出し、節、情報の取捨 |
| 修辞 | `rhetoric.md` | 構文の型とリズム |
| 語彙 | `vocabulary.md` | 語の選択 |
| 記号 | `symbols.md` | 記号と字面 |

## 検出対象

- 立場
    - 反証できない主張
    - 結論の回避
    - 弱い否定
    - 強度の振り切り
    - 裏を取らない伝聞
    - ヘッジの重ね掛け
    - 儀式化した免責
    - Praising everything
- 主体
    - false agency
    - 実装判断の壮大化
    - 受動態
    - 自動詞化
    - 遠くから語る話者
    - 一般論だけの段落
    - 翻訳調動詞
    - Missing first person
- 箇条書き
    - 平坦な箇条書き
    - 1項目への詰め込み
    - 条件と処置の同居
    - 階層の付け間違い
    - 段落に流した並列
- 文書構成
    - 命題型の見出し
    - 見出しから導ける本文
    - 見出しと中身のずれ
    - しないことの記述
    - 経緯の記録
    - 例外条項の後付け
    - メタ的な構造宣言
    - 目的の言えない情報
    - 太字の疑似見出しとスコープ外の節
    - The head of a design document
- 修辞
    - 二項対比
    - 否定的列挙
    - 劇的な断片化
    - 一文圧縮
    - 3項目並列
    - ムラの欠如
    - 段落の均一な閉じ方
    - pull-quote調
    - 文頭のクセ
    - 余った断定と動作の名詞化
- 語彙
    - 英語固有名詞の律儀さ
    - `scripts/rules/<lang>.pl` の語
- 記号
    - 括弧による後置補足
    - 評価を囲む鉤括弧
    - Scare quotes

## 手順

### 1. 対象の確定

`$1` を起点にする

- ディレクトリの場合
    - Globでファイルを集める
    - 対象をユーザーに確認する
    - ファイルごとにステップ2から繰り返す
- 会話中の下書きの場合
    - 一時ファイルに書き出す
- これから書く場合
    - 先に下書きを最後まで書く
    - 一時ファイルに書き出す
- ユーザーが渡さなかった場合
    - 対象を聞く

### 2. レビューの実行

```bash
bash ~/.claude/skills/readable-writing/scripts/review.sh <ファイルパス>
```

### 3. 指摘の整理

- 重複の統合
    - 同じ `quote` についての指摘は1件にする
- 修正の並び順
    - 同一ファイル内は行番号の昇順
- 指摘の採否
    - `quote` が本文に実在するかだけで決める
    - 書き先の慣例と食い違う指摘も直す
        - コミットメッセージの72桁折り返しより `文中での改行` の指摘を優先する

### 4. 修正

- 対象ファイルをReadで開く
    - `quote` の前後を読む
- `fix` がある場合
    - 前後の文と繋がるように書き換えてから使う
- `fix` が `null` の場合
    - `problem` を読む
    - 前後の文に合う形に書き換える
- 同一段落への修正が複数ある場合
    - 段落ごとにまとめて書き換える
- 修正の順序
    1. 先に直す
        - 立場
        - 主体
    2. 段落を組み直す
        - 箇条書き
        - 文書構成
        - 修辞
    3. 本文に残っていないか確かめる
        - 語彙
        - 記号
- 書き換えた文に `## 検出対象` の名前を当てる
    - 当たった名前の節を、その観点のポリシーをReadで開いて読む
    - `AI版` と `修正版` の対比から直し方を取る
    - 書き直した文にも名前を当てる
- 書き換えで足せるもの
    - 修正前の本文にある情報
    - ユーザーが会話で渡した情報
    - これ以外は足さない
        - 留保
        - 免責
        - 未検証であることの断り
        - 読み手が聞いていないことへの先回り
- 指摘のある箇所のみ書き換える

### 5. 成果物の提示

- ファイルが対象の場合
    - Editで書き換える
    - 指摘が0件の場合
        - 「修正なし」と返す
- 一時ファイルに書き出した場合
    - ユーザーが書き先を指定している場合
        - Writeで置く
    - 指定していない場合
        - 修正後の本文だけを出力する
