# 立場

## 検出対象

### 反証できない主張

- `本質的な問題がある`
- `構造的な課題である`
- `示唆に富む結果だ`
- `重大な意味を持つ`
- `根本的な転換が必要だ`
- `深い洞察が得られる`
- `重要な示唆を含む`
- `○○することが大切です`
- `○○に他なりません`

#### AI版

```
このリファクタリングには本質的な問題がある。構造的な課題であり、根本的な転換が必要だ。
```

#### 修正版

```
このリファクタリングでは、`OrderService` が `PaymentGateway` を直接呼んでいる箇所が7つ残った。
```

### 結論の回避

- `ケースバイケース`
- `場合によります`
- `価値観によります`
- `状況に応じて異なります`
- `一概には言えませんが`
- `一般的には`
- `メリットもあればデメリットもあります`
- `○○という側面もありますが、一方で〜`
- `賛否が分かれるテーマです`
- `それぞれに独自の強みがあり、用途による`

#### AI版

```
モノレポにするかどうかはケースバイケースです。メリットもあればデメリットもあり、一概には言えません。
```

#### 修正版

```
モノレポにした。パッケージが3つしかなく、バージョンを揃える手間のほうが大きかった。
```

#### 修正の型

- 決めた結論を最初の一文に置く
- 理由をそのあとに続ける

### 弱い否定

- `あまり推奨されません`
- `注意が必要です`
- `望ましくないとされています`
- `避けたほうが良いでしょう`

- ファイル数が増えると遅くなる可能性があるため、注意が必要です
    - ファイルが1000を超えると、この方式は1回1分以上かかる

### 強度の振り切り

- `劇的に改善`
- `圧倒的に速い`
- `大幅に削減`
- `飛躍的に向上`
- `爆速`
- `絶対に避けるべき`
- `論外`

#### AI版

```
インデックスを張ったらクエリが劇的に改善した。爆速になったと言っていい。

この構成は論外だ。絶対に避けるべきだ。
```

#### 修正版

```
インデックスを張ったら、このクエリが平均1200msから40msになった。

この構成はリクエストごとに接続を張り直すので、同時100リクエストでDBの接続上限に当たる。
```

### 根拠のない強い評価

- `非常に有効です`
- `画期的な手法です`
- `革新的なアプローチです`
- `大きなメリットがあります`
- `驚くべき効果が期待できます`

#### AI版

```
この手法は非常に有効です。画期的なアプローチで、大きなメリットがあります。
```

#### 修正版

```
過去3ヶ月のPRを120本見た。この手法を入れてから、レビュー待ちの平均が2日から半日になっている。
```

### ヘッジの重ね掛け

- `○○ことがある`
- `○○場合がある`
- `○○可能性がある`
- `○○なりうる`
- `○○とは限らない`
- `○○と言えなくもない`
- `あくまで○○として捉えるのが正確だ`

- 組織の規模によって結果は異なる可能性がある
    - 10人規模のウチのチームでの話

### 儀式化した免責

- `あくまで個人の経験に基づく見解であり、定量的な検証ではない`
- `環境やケースによって結果は異なる可能性がある`
- `実装はモデルによって異なる`

#### AI版

```
私のチームではこの方法でリリース頻度が上がった。ただし、これはあくまで個人の経験に基づく見解であり、定量的に検証したものではない。組織の規模や文化によって結果は異なる可能性があるため、参考程度に捉えていただきたい。
```

#### 修正版

```
10人規模のウチのチームでは、この方法でリリース頻度が週1から週3に上がった。
```

#### 修正の型

- 保険は具体的な適用範囲として1回だけ書く
    - `10人規模のウチのチームでは`
- 主張はそのまま残す
