# 修辞

## 検出対象

### 余った断定

- 断定の助辞で文を閉じる形
    - `だ`
    - `である`
    - `です`
- 動作を名詞化した体言止め

#### AI版

```
形態素解析器の置き換えは、複合語の検索漏れをなくすためである。Kuromojiでは「機械学習」が「機械」と「学習」に割れるのが原因だ。移行の対象はインデックスの再構築までです。
```

#### 修正版

```
形態素解析器を置き換えたのは、複合語の検索漏れをなくすため。Kuromojiでは「機械学習」が「機械」と「学習」に割れていた。移行の対象はインデックスの再構築まで。
```

#### 修正の型

- 落とす助辞
    - `だ`
    - `である`
    - `です`
- 地の文の動作
    - 採用する形
        - `削除した`
    - 避ける形
        - `削除を実施`

### 二項対比

- `Aではなく、Bである`
    - `B`
- `単なるAではなく、Bだ`
    - `B`
- `Aだけじゃなく、Bでもある`
    - `B`
- `実はAではなくBだった`
    - `Bだった`
- `Aに見えるが、Bだ`
    - `B`
- `Aではなくなり、Bになる`
    - `Bになった`
- `重要なのはAではなくBだ`
    - `Bを優先した`

#### AI版

```
これは単なる効率化ツールではない。これは思考のパートナーだ。
AIは置き換えるためのものではなく、拡張するためのものだ。
重要なのは速度ではなく、深さである。
```

#### 修正版

```
AIに下書きを書かせると、自分の考えを言語化しやすくなる。検討の幅も広がる。書く速さは変わらないが、検討の抜けが減った。
```

### 否定的列挙

- `Aではない。Bでもない。Cだ。`
    - `C`
- `これは戦略ではなく、戦術でもなく、習慣だ`
    - `これは習慣`
- `彼は研究者でも、エンジニアでもなく、職人だった`
    - `彼は職人だった`

### 劇的な断片化

短い単語文を並べ、句点で間を作ろうとする形。

- `シンプル。それだけ。それが本質。`
    - `ハンドラ1つと設定ファイル1つで動く`
- `速く。正確に。継続的に。`
    - `毎回同じ手順で、待たずに終わる`
- `これがすべてを変える。本当に。すべてを。`
    - `レビューの往復が3回から1回になった`

#### AI版

```
これは小手先のテクニックではない。一時的な流行でもない。働き方そのものの変化だ。
速く。深く。そして静かに。それが、これからのスタンダードになる。
```

#### 修正版

```
これは開発の進め方そのものが変わる話だと思う。気づいたら当たり前になっている。
```

#### 修正の型

3つ以上並んだ短文を1つの長い文にまとめる。

### 修辞疑問

- `なぜか。`
- `どういうことか。`
- `本当にそうだろうか。`

#### AI版

```
Claudeで書いたドキュメントが、レビューで「読みにくい」と返ってきた。なぜか。どういうことか。
```

#### 修正版

```
Claudeで書いたドキュメントが、レビューで「読みにくい」と返ってきたので、指摘の内容を集計した。
```

#### 修正の型

`なぜか` は `集計した` のような、次にやったことに置き換える。

### 決めつけ序文

#### AI版

```
Claudeを使えば誰でも質の高いドキュメントが書ける──そう信じて導入したチームは多いはずだ。しかし、いざレビューに出すと「読みにくい」と返ってくる。なぜか。
```

#### 修正版

```
Claudeで設計ドキュメントを書くようになって半年経つが、レビューで「読みにくい」と指摘されることが増えた。どこが読みにくいのか言語化できていなかったので、指摘の内容を集計した。
```

### 定型の語り出し

- `気づいたときには、すでに○○だった`
- `あの日、私は○○していた`

#### AI版

```
気づいたときには、すでにビルドは9分かかっていた。あの日、私はCIのログをただ眺めていた。
```

#### 修正版

```
9月にCIのログを見て、初回ビルドに9分かかっていることに気づいた。
```

### 一文圧縮

#### AI版

```
JavaScriptは1995年にBrendan Eichが10日間で設計した。この言語は瞬く間に普及した──しかし型安全性は設計目標に含まれていなかった。
```

#### 修正版

```
JavaScriptは、もともと1995年にBrendan Eichが作った言語。10日ほどで設計されたらしい。そこから急速に普及し、今のWebの標準になった。ただ、Brendan Eichは開発当時、型安全性をあまり考えていなかったようだ。TypeScriptはそこを埋めるために生まれた。
```

#### 修正の型

- 1文に詰めた事実を、事実ごとに文へ分ける
- 調べただけの事実には伝聞表現を付ける
    - `らしい`
    - `ようだ`
    - `と聞いた`

### ムラの欠如

#### AI版

```
Sudachiに置き換えて、複合語の検索漏れが消えた。精度は着実に上がっている。

インデックスの再構築には3時間かかった。想定の範囲内で終わっている。

運用チームへの引き継ぎも終わった。手順書も整備できている。
```

#### 修正版

```
Sudachiに置き換えて、「機械学習」が「機械」と「学習」に割れなくなった。

インデックスの再構築は3時間かかるので、夜間に流した。

引き継ぎはまだ手応えがない。手順書は書いたが、運用チームが自分で直せる状態かどうかは、やってみるまで分からない。
```

### 段落の均一な閉じ方

- 感想で閉じる形
    - `〜なんだなと感じました`
    - `〜ということが分かりました`
    - `〜の重要性を痛感しました`
- 効能で閉じる形
    - `これにより〜が向上します`

#### AI版

```
キャッシュを挟んだら9分のビルドが3分になった。効果の大きさを痛感しました。

CIのコストも下がった。これにより運用費が改善します。

待ち時間も減った。集中が続くということが分かりました。
```

#### 修正版

```
キャッシュを挟んだら9分のビルドが3分になった。

CIのコストも下がったはずだ。請求書はまだ見ていない。

待ち時間が減って、ブランチを切り替えて別の作業を始めることがなくなった。
```

#### 修正の型

- 感想の閉じ方を消す
- 効能の閉じ方
    - 観測した事実に置き換える
    - まだ確かめていないなら、確かめていないと書く

### 文頭のクセ

- `実は、` で始まる文
    - 削除する
- `そして、` の連続
    - 崩す
- `また、` の連続
    - 崩す

#### AI版

```
実は、キャッシュのキー設計に問題があった。そして、`package-lock.json` のハッシュを使うようにした。また、`.next/cache` も対象に含めた。そして、ビルドが3分になった。
```

#### 修正版

```
キャッシュのキー設計に問題があった。`package-lock.json` のハッシュを使い、`.next/cache` も対象に含めたら、ビルドが3分になった。
```

## 検出手順

1. 次の形で終わる文を集める
    - `だ。`
    - `である。`
    - `です。`
2. 助辞を落として意味が変わらない文を指摘する
3. 対比の構文を探す
    - `ではなく`
    - `だけでなく`
    - `に見えるが`
4. 3つ以上続く短文を集める
    - 単語だけで閉じた文
    - 否定を重ねた文
5. 疑問で終わる地の文を集める
    - `なぜか。`
    - `どういうことか。`
    - `本当にそうだろうか。`
6. 冒頭の段落を読む
    - 読み手の状態を決めつけた文を集める
    - 定型の語り出しを集める
7. 事実を並べた文を集める
    - 調べただけの事実に伝聞表現が付いているか確かめる
8. 段落の末尾の文を集める
    - 感想で閉じた文
    - 効能で閉じた文
9. 段落ごとに文の長さと語尾を並べる
    - 同じ形が続く箇所を集める
10. 文頭の語を集める
    - `実は、`
    - 連続する `そして、`
    - 連続する `また、`
