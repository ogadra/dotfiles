# 語彙

日本語の語彙を見る。単語と決まり文句で検出できるものが対象。文と文の並べ方に出る型は `common/rhetoric.md` にある。

系統でまとめた語は、同じ系統から2語以上、または同じ語が3回以上出ると読みにくくなる。

## 検出対象

### 表層の定型句

この語が1つでも出れば、読み手はAIが書いたと分かる。

- `いかがでしたでしょうか`
- `いかがでしたか`
- `ぜひ参考にしてください`
- `ぜひ〜してみてください`
- `○○の重要性を再認識しました`
- `近年〜が注目されています`
- `現代社会において〜は重要なテーマです`

#### AI版

```
近年、CIの高速化が注目されています。本記事ではキャッシュの導入方法をご紹介しました。いかがでしたでしょうか。ぜひ参考にしてみてください。
```

#### 修正版

```
`actions/cache` を足したら初回ビルドが9分から3分になった。キーには `package-lock.json` のハッシュを使っている。
```

#### 修正の型

定型句を含む文ごと消す。消したあとに何も残らないなら、その段落は要らない。

### 咳払いの前置き

本題に入る前の時間稼ぎ。

- `実はですね、`
- `結論から言うと`
- `正直に言うと`
- `率直に言いますが`
- `ここで重要なのは`
- `ひとつ言っておきたいのは`
- `結局のところ`
- `本当のところ`
- `あえて言うなら`

#### AI版

```
結論から言うと、ここで重要なのは、キャッシュのキー設計だ。
```

#### 修正版

```
キャッシュのキーには `package-lock.json` のハッシュを使う。
```

#### 修正の型

前置きを消して、本題の文から始める。

### 曖昧な指示語

前に書いたことを指し示すだけで、何を指しているかを書かない語。読み手は前の記述に戻って復元する必要がある。

- 〜も同じ
- 同様に
- 同じく
- 上記の通り
- 前述の

#### 修正の型

何がそうなのかを書く。

| 避ける | 使う |
|---|---|
| 「以前は」も同じ | 「以前は」も残さない |
| 同様に、括弧も使わない | 括弧も使わない |
| 上記の通り、1段下げる | 理由と補足を1段下げる |

### 横文字メタファー

IT用語を、本来の対象以外に比喩で持ち込む形。

| 避ける | 使う |
|---|---|
| 思考のOSをアップデートする | 考え方を変える |
| 人生をハックする | 工夫する、コツを掴む |
| 新しい習慣をインストールする | 習慣をつける |
| マインドをリファクタリングする | 考え方を整理する |
| 頭の中にラボを持つ | 頭の中で試す |
| キャリアをポートフォリオで考える | 仕事の組み合わせで考える |
| 学びをアセットにする | 学びを積み上げる |

#### AI版

```
大事なのは、チームの思考のOSをアップデートすること。新しいレビュー習慣をインストールし、古いマインドをリファクタリングする。開発フローをハックする視点を持てば、生産性は変わる。
```

#### 修正版

```
レビューの出し方を変えて、PRを小さく分ける習慣をつけ、前提になっていた運用を見直した。それだけでレビュー待ちがかなり減った。
```

#### 修正の型

IT用語を全部、普通の日本語に戻す。「生産性は変わる」のような抽象的な大言は、具体的な効果に置き換える。

### ビジネスジャーゴン

普通の言葉に置き換える。

| 避ける | 使う |
|---|---|
| 〜にコミットする | 〜をやる、〜を引き受ける |
| 〜にレバレッジを効かせる | 〜を活用する |
| 〜の解像度を上げる | 〜を詳しく知る、〜を理解する |
| 〜にディープダイブする | 〜を深く見る、〜を調べる |
| 〜をアラインする | 〜を揃える、〜を合わせる |
| 〜のスケールを取りに行く | 〜を広げる |
| ROIを最大化する | 効率を上げる |
| 〜にピボットする | 〜に方針転換する |

### 文末の敬体

文末に「です」「ます」が混ざる形。

#### AI版

```
リトライは3回までです。3回を超えた場合はDLQに送ります。アラートも飛ばします。
```

#### 修正版

```
リトライは3回まで。3回を超えたらDLQに送り、アラートを飛ばす。
```

#### 修正の型

常体に揃える。

    - 設計

### 必殺技造語

個別の技術判断を、必殺技のような漢字熟語で大きな話に仕立てる語。`common/agency.md` の実装判断の壮大化と連動する。

    - 真実
- 到達点系
    - 結末
    - 結実
    - 宿命
    - 運命
    - 境地
    - 極致
    - 究極
- 虚系
    - 虚飾
    - 装飾
    - 虚像
- 良いとされているもの系
    - 美学
    - 徳
    - 品性
- 奥深い系
    - 重厚感
    - 深淵
    - 禁欲的
- 感情系
    - 優美
    - 繊細
- 理性系
    - 残酷
    - 冷徹
    - 冷酷
    - 過酷
- 圧縮系
    - 凝縮
    - 結晶

複合させた形も避ける。

- `枯淡の境地`
- `冷徹な結末`
- `残酷な真理`
- `虚飾を剥ぎ取る`
- `禁欲的な美学`
- `重厚感の欠如`

#### AI版

```
二つのロギングライブラリと向き合った三ヶ月。zapの「禁欲的」なAPIと、logrusの「優美な」拡張性。ベンチマークの数字を毎日眺め続けた末に辿り着いた、ある「真実」。スループットという「虚飾」を剥ぎ取った時、我々が本当に必要としていたものとは──。
```

#### 修正版

```
zapとlogrusを3ヶ月ずつ試して、zapにした。logrusは構造化ログのフィールド追加が遅く、ホットパスで無視できない差が出た。
```

#### 修正の型

一つのライブラリを選んだ話を、業界全体の課題のように膨らませない。「真実」も「虚飾」も「禁欲的」も要らない。

### 過剰なカタカナ表記

普通の日本語に戻せるカタカナ語。

| 避ける | 使う |
|---|---|
| コンテキスト | 状況、前後関係 |
| アライメント | 揃える、合わせる |
| コミュニケーション | 話す、伝える |
| インテグリティ | 誠実さ、一貫性 |
| コラボレーション | 共同作業、連携 |
| インプリメンテーション | 実装 |
| プライオリティ | 優先 |
| アグリー | 同意、賛成 |
| ナレッジ | 知識、ノウハウ |

技術用語は技術用語のまま書く。普通の日本語で言えるところまでカタカナにすると、読み手が引っかかる。

### 副詞の重ね掛け

根拠なし副詞。1段落に2個以上重なったら指摘する。

- 非常に
- とても
- かなり
- 本当に
- 実に
- 確かに

#### AI版

```
このライブラリは非常に軽量で、とても扱いやすい。本当に導入する価値がある。
```

#### 修正版

```
このライブラリはgzip後で12KB、依存は0本。`import` して関数を呼ぶだけで動く。
```

#### 修正の型

副詞を消し、程度を数字で書く。数字を出せないなら副詞ごと削る。

### 英語固有名詞の律儀さ

正式名称を毎回フルで書く形。

#### AI版

```
OpenAIが発表したGPT-5は、Anthropicが発表したClaude 4や、Googleが発表したGemini 3よりも出力が速い。
```

#### 修正版

```
GPT-5の出力は、Claude 4とGemini 3より速い。
```

#### 修正の型

2度目以降は社名やバージョンを省略する。フル正式名称が3つ以上並んだら指摘する。

## 検出手順

1. 文字列検索する
    - 表層の定型句
    - 咳払いの前置き
    - 曖昧な指示語
    - 横文字メタファー
    - ビジネスジャーゴン
    - 過剰なカタカナ表記
    - 1件でも出れば指摘する
2. 文字列検索して系統ごとに出現回数を数える
    - AI偏愛語
    - 必殺技造語
    - 比喩のテンプレ語
    - 同じ系統から2語以上出たら指摘する
    - 同じ語が3回以上出たら指摘する
3. 文末を集め、「です」「ます」が混ざっていないか確かめる。
4. 段落ごとに副詞の数を数える。
5. 固有名詞を集め、2度目以降が省略されているか確かめる。
