# 記号

## 検出対象

### 評価を囲む鉤括弧

- `「禁欲的」なAPI`
    - `機能を絞ったAPI`
- `ある「真実」`
    - `分かったこと`

### 間を作る読点

読み手が止まる必要のない所に読点を打っている。

- 文頭の短い主題のあと
    - `原因は、`
    - `CIでは、`
- `を` のあと
    - `ハッシュを、`

#### AI版

```
原因は、キャッシュのキーの誤りだった。`package-lock.json` のハッシュを、キーに含めた。
```

#### 修正版

```
原因はキャッシュのキーの誤りだった。`package-lock.json` のハッシュをキーに含めた。
```

#### 修正の型

- 外しても掛かり先が変わらない読点の場合
    - 読点だけを外す
    - 語順と述語は変えない
- 外すと掛かり先が変わる読点の場合
    - 残す
    - `店長は、慌てて逃げた客を追いかけた`
- 主題のあとに別の主語が続く読点の場合
    - 残す
    - `会議では、担当者が説明した`

### 全角の英数字

- `２０２６年`
    - `2026年`
- `ＡＰＩ`
    - `API`

#### AI版

```
ＣＩの所要時間が９分から３分になった。
```

#### 修正版

```
CIの所要時間が9分から3分になった。
```

#### 修正の型

`scripts/mechanical.pl` の `fix` はインラインコードとURLの外にある全角の英数字を半角にする。

- 正式な表記が全角の固有名詞を含む場合
    - 固有名詞の外だけを手で半角にする
- 含まない場合
    - `fix` をそのまま使う

## 検出手順

1. 鉤括弧で囲んだ語を集める
    - 固有名詞でも直接引用でもないものを指摘する
2. 読点を集める
    - 直前が文頭の短い主題のものを指摘する
    - 直前が `を` のものを指摘する
3. 全角の英字と数字を集める
