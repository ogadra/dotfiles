# 修辞

## パターン

### 要らない断定と動作の名詞化

- 断定の助辞で文を閉じる形
    - `だ`
    - `である`
    - `です`
- 動作を名詞化した体言止め

#### AI版

```
形態素解析器の置き換えは、複合語の検索漏れをなくすためである。Kuromojiでは「機械学習」が「機械」と「学習」に割れるのが原因だ。移行の対象はインデックスの再構築までです。
```

#### 修正版

```
形態素解析器を置き換えたのは、複合語の検索漏れをなくすため。Kuromojiでは「機械学習」が「機械」と「学習」に割れていた。移行の対象はインデックスの再構築まで。
```

#### 修正の型

- 断定の助辞を落とす
- 地の文の動作は動詞で書く
    - `削除した`

### 二項対比

- `Aではなく、Bである`
    - `B`
- `単なるAではなく、Bだ`
    - `B`
- `Aだけじゃなく、Bでもある`
    - `B`
- `実はAではなくBだった`
    - `Bだった`
- `Aに見えるが、Bだ`
    - `B`
- `Aではなくなり、Bになる`
    - `Bになった`
- `重要なのはAではなくBだ`
    - `Bを優先した`

#### AI版

```
これは単なる効率化ツールではない。これは思考のパートナーだ。
AIは置き換えるためのものではなく、拡張するためのものだ。
重要なのは速度ではなく、深さである。
```

#### 修正版

```
AIに下書きを書かせると、自分の考えを言語化しやすくなる。検討の幅も広がる。書く速さは変わらないが、検討の抜けが減った。
```

### 否定の前置き

- `Aではない。Bでもない。Cだ。`
    - `C`
- `これは戦略ではなく、戦術でもなく、習慣だ`
    - `これは習慣`
- `彼は研究者でも、エンジニアでもなく、職人だった`
    - `彼は職人だった`

### 短文の連打

- `シンプル。それだけ。それが本質。`
    - `ハンドラ1つと設定ファイル1つで動く`
- `速く。正確に。継続的に。`
    - `毎回同じ手順で、待たずに終わる`
- `これがすべてを変える。本当に。すべてを。`
    - `レビューの往復が3回から1回になった`

#### AI版

```
これは小手先のテクニックではない。一時的な流行でもない。働き方そのものの変化だ。
速く。深く。そして静かに。それが、これからのスタンダードになる。
```

#### 修正版

```
これは開発の進め方そのものが変わる話だと思う。気づいたら当たり前になっている。
```

#### 修正の型

3つ以上並んだ単語だけの文を1つの文にまとめる。

### 一文圧縮

#### AI版

```
JavaScriptは1995年にBrendan Eichが10日間で設計した。この言語は瞬く間に普及した──しかし型安全性は設計目標に含まれていなかった。
```

#### 修正版

```
JavaScriptは、もともと1995年にBrendan Eichが作った言語。設計にかけたのは10日ほどだ。そこから急速に普及し、今のWebの標準になった。ただ、Brendan Eichは開発当時、型安全性をあまり考えていなかった。TypeScriptはそこを埋めるために生まれた。
```

#### 修正の型

1文に詰めた事実を事実ごとに文へ分ける。

### そろいすぎた段落

#### AI版

```
Sudachiに置き換えて、複合語の検索漏れが消えた。精度は着実に上がっている。

インデックスの再構築には3時間かかった。想定の範囲内で終わっている。

運用チームへの引き継ぎも終わった。手順書も整備できている。
```

#### 修正版

```
Sudachiに置き換えて、「機械学習」が「機械」と「学習」に割れなくなった。

インデックスの再構築は3時間かかるので、夜間に流した。

引き継ぎはまだ手応えがない。手順書は書いたが、運用チームが自分で直せる状態かどうかは、やってみるまで分からない。
```

### 段落の均一な終わり方

- 感想で閉じる形
    - `〜なんだなと感じました`
    - `〜ということが分かりました`
    - `〜の重要性を痛感しました`
- 効能で閉じる形
    - `これにより〜が向上します`

#### AI版

```
キャッシュを挟んだら9分のビルドが3分になった。効果の大きさを痛感しました。

CIのコストも下がった。これにより運用費が改善します。

待ち時間も減った。集中が続くということが分かりました。
```

#### 修正版

```
キャッシュを挟んだら9分のビルドが3分になった。

CIのコストも下がったはずだ。請求書はまだ見ていない。

待ち時間が減って、ブランチを切り替えて別の作業を始めることがなくなった。
```

#### 修正の型

- 感想の閉じ方
    - 消す
- 効能の閉じ方
    - 置き換え先
        - 観測した事実
        - まだ確かめていない旨

### 文頭のクセ

- `実は、` で始まる文
    - 削除する
- `そして、` が文頭に続く文
    - その語を消して前の文とつなぐ
- `また、` が文頭に続く文
    - その語を消して前の文とつなぐ
- `さらに、` が段落の頭に続く文
    - その語を消して前の段落とつなぐ
- `加えて、` が段落の頭に続く文
    - その語を消して前の段落とつなぐ
- `なお、` で同じ話を切った文
    - 前の文につなぐ
- `もちろん、` に数語だけが続く短い文
    - 削除する

#### AI版

```
実は、キャッシュのキー設計に問題があった。そして、`package-lock.json` のハッシュを使うようにした。また、`.next/cache` も対象に含めた。そして、ビルドが3分になった。
```

#### 修正版

```
キャッシュのキー設計に問題があった。`package-lock.json` のハッシュを使い、`.next/cache` も対象に含めたら、ビルドが3分になった。
```

#### AI版

```
初回ビルドは3分になった。なお、2回目以降は30秒のままだ。もちろん、例外もある。
```

#### 修正版

```
初回ビルドは3分になり、2回目以降は30秒のままだった。
```

### 主語と述語のねじれ

- `この変更の目的はビルドを速くする。`
    - `この変更の目的はビルドを速くすることだ。`
- `ワーカーではキューの長さを数え、上限を超えたら止めるため、MAX_JOBSを定義する。`
    - `ワーカーはキューの長さを数える。長さがMAX_JOBSを超えたら、ワーカーは新しいジョブを受け付けない。`

#### AI版

```
古いキャッシュを消すために設定ファイルを読み込んだあとで起動時に毎回確認する処理を足した。
```

#### 修正版

```
起動時に設定ファイルを読み込み、古いキャッシュがあれば消す処理を足した。
```

#### 修正の型

- 主語と述語が離れている場合
    - 長い修飾を先に置き、主語を述語の近くに移す
- 主語と述語がかみ合わない場合
    - 述語を主語に合わせて書き直す
- 文の途中で動作主が変わる場合
    - 変わる所に動作主を書く
- 掛かり先が2通りに読める場合
    - 書き手に確かめる

### 一文に重ねた「は」

- `今回は、この画面は`
    - `今回の画面は`

#### AI版

```
今回の変更では、キャッシュは、初回ビルドでは効かない。
```

#### 修正版

```
今回の変更でも初回ビルドにはキャッシュが効かない。
```

#### 修正の型

- 話題を示す「は」を1文に1つにする
- 新しく出す物や起きた出来事を「が」で書く

### 「の」の連続

処理や確認のような動作を表す名詞を2つ以上含む語を「の」で3つ以上つないでいる。

- `処理の実行の完了の確認後に`
    - `処理が終わったことを確かめてから`

#### AI版

```
検証の結果の傾向の分析の手順は付録に書いた。
```

#### 修正版

```
検証の結果から傾向を分析した手順は、付録に書いた。
```

#### 修正の型

「の」でつないだ名詞の一部を助詞と動詞の形に戻す。

### 逆接でない「が、」

- `キャッシュを入れたが、ビルドが3分になった。`
    - `キャッシュを入れたら、ビルドが3分になった。`

#### AI版

```
設定を見直したが、エラーが消えた。テストも足したが、すべて通った。
```

#### 修正版

```
設定を見直したらエラーが消えた。足したテストもすべて通った。
```

#### 修正の型

- 「が、」の前が理由の場合
    - 「ので」でつなぐ
- 「が、」の前が条件の場合
    - 「たら」でつなぐ
- 「が、」の前と後ろに関係が無い場合
    - 文を分ける

### 倒置

- `速くなった、キャッシュを入れたことで。`
    - `キャッシュを入れて速くなった。`

#### AI版

```
ビルドが3分になった、キャッシュのキーを直したことで。
```

#### 修正版

```
キャッシュのキーを直して、ビルドが3分になった。
```

#### 修正の型

主語、目的語、述語の順に戻す。

## 検出手順

1. 「要らない断定と動作の名詞化」の節にある形で終わる文を集める
2. 助辞を落として意味が変わらない文を指摘する
3. 対比の構文を探す
    - `ではなく`
    - `だけでなく`
    - `に見えるが`
4. 3つ以上続く文を集める
    - 単語だけの文
    - 否定を重ねた文
5. 事実を並べた文を集める
    - 調べただけの事実に出典が付いているか確かめる
6. 段落の末尾の文を集める
    - 感想で終わる文
    - 効能で終わる文
7. 段落ごとに並べる
    - 文の長さ
    - 語尾
8. 並べた段落で同じ形が続く箇所を集める
9. 文頭のクセの節にある語で始まる文を集める
10. 各文の主語と述語を抜き出す
    - 述語が主語の動作か状態を表しているか確かめる
    - 間に長い修飾が挟まっていないか確かめる
11. 「は」が2つ以上ある文を集める
12. 「の」を3つ以上重ねた箇所を集める
    - そのうち動作を表す名詞を2つ以上つないだものを指摘する
13. 「が、」でつないだ文を集める
    - 前と後ろが逆の内容か確かめる
14. 述語のあとに読点を挟んで続きを置いた文を集める
    - 目的語が続く文
    - 理由が続く文
